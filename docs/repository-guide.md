# Repository Guide

This guide is a quick orientation for contributors working in Roster. It explains
where the main responsibilities live and which commands to use before changing
a subsystem. The [root README](../README.md) remains the best introduction to
Roster's product model and the example applications.

## What the repository contains

Roster is a TypeScript coordination framework for bounded, replayable multi-agent
workflows. The repository includes the public SDK, orchestration and runtime
engines, a SpacetimeDB coordination module, browser clients, and reference
workflows for theorem proving, writing, coding, and visual composition.

The durable coordination boundary is SpacetimeDB. Receipts represent ordered
control transitions; bounded shared-artifact ledgers preserve independent
contributions; Git or object storage is used for source trees and large
artifacts. A runtime executes work for a logical workspace node, but it does not
own topology, budgets, certification, or acceptance decisions.

## Repository map

- `src/core/` — canonical encoding, hashing, receipt chains, and low-level runtime primitives.
- `src/engine/orchestration/` — plans, topology, task composition, distributed control, and certification.
- `src/engine/runtime/` — scheduling, leases, model execution, limits, workers, and runtime transports.
- `src/engine/workspace/` — logical node identity, runtime bindings, projections, and bounded shared workspaces.
- `src/engine/artifact/` — the generic add-only Yjs artifact protocol.
- `src/agents/` — first-party agent workflows and discoverable `*.agent.ts` modules.
- `src/domains/` — domain-specific plans, capabilities, artifact validation, and acceptance policies.
- `src/modules/` — receipt types and deterministic state reducers.
- `src/adapters/` — integrations for SpacetimeDB, OpenAI, AXLE, queues, and web access.
- `src/framework/` — module loading, headless execution, HTTP helpers, and schemas.
- `src/browser/` — realtime browser clients, renderers, and replay controllers.
- `spacetimedb/` — database tables, views, reducers, authorization, and lease recovery.
- `prompts/` — versioned structured prompt configurations.
- `packages/pi-roster/` — the Pi package and Roster extension.
- `tests/smoke/` — integration-oriented runtime, replay, CRDT, UI, database, and failure tests.
- `tests/deterministic/` — deterministic AXLE tool-surface tests.
- `docs/` — architecture, operation, extension, and example documentation.

Generated browser output, SDK declarations, SpacetimeDB bindings, local state,
tokens, and runtime data should be regenerated by the documented commands
rather than edited by hand.

## Local development loop

Install dependencies first:

```bash
npm install
npm --prefix spacetimedb install
```

For changes that involve the database contract, build and regenerate before
building the application:

```bash
npm run spacetime:build
npm run spacetime:generate
npm run build
```

For ordinary TypeScript or documentation changes, the application build is
usually sufficient. The complete repository gate is:

```bash
npm run verify
```

`verify` builds the server and browser clients, checks for explicit `any` in
core surfaces and unused declarations, then runs deterministic and smoke tests.
Database-backed tests additionally require a running, locally published
SpacetimeDB module; see [`docs/spacetimedb.md`](./spacetimedb.md).

## Change boundaries

When changing a public node, runtime, orchestration, or shared-artifact boundary:

1. Use the platform-v3 node/task contract throughout: `WorkspaceNode`,
   `DynamicTaskDefinition`, `AcceptedTaskOutcome`, `RunExecutionPolicy`, and
   `nodeId` in tasks, artifacts, and composition.
2. Keep logical node identity separate from runtime bindings, leases, processes,
   sessions, worktrees, and sandboxes.
3. Keep runtime adapters focused on bounded inner-loop execution. Roster remains
   responsible for tasks, topology, receipts, budgets, conflicts, and
   certification.
4. Preserve semantic conflicts instead of resolving them by arrival order.
5. Keep the registry surface to `node`, `nodesFor`, `assertNodeAssignment`, and
   `extendNodes`; do not add agent-named aliases, old orchestration payload
   fallbacks, or Coding dual-read paths.
6. Update the nearest architecture document and add a targeted smoke test when
   behavior changes.

When documentation and implementation disagree, treat source code and tests as
authoritative, then update the documentation in the same change.
